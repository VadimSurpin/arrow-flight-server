# Частичная агрегация Flight → Trino

Ветка: `feat/trino-partial-aggregation-pushdown`. База движка: Trino 446,
зафиксированная в `flight-trino/trino-fork/BASE_SHA`.

## Как выполняется запрос

Пользователь пишет обычный SQL. Патч планировщика заменяет поддерживаемый PARTIAL
чтением промежуточных состояний из Flight. Для исходного SINGLE сохраняется FINAL
над чтением состояний. DuckDB на каждой Flight-ноде вычисляет свою часть, а штатные
Exchange и финальная агрегация Trino объединяют результат. Запускать Trino workers
рядом с каждой Flight-нодой не требуется.

```sql
SET SESSION flight.partial_aggregation_pushdown = true;

SELECT k, count(*), min(v), max(v), sum(v), avg(v)
FROM flight.test_schema.grouped
GROUP BY k;
```

Свойство выключено по умолчанию. На стандартном Trino без engine patch оно не
включает частичный pushdown. Сборка и команды проверок описаны в
[README патча](../../flight-trino/trino-fork/README.md).

## Что поддержано

| Операция | Вход | Что возвращает Flight | Что получает FINAL |
| --- | --- | --- | --- |
| COUNT | Целые, BOOLEAN, VARCHAR, DOUBLE; также COUNT(*) | Количество ненулевых значений либо строк | BIGINT |
| MIN/MAX | BIGINT, INTEGER, SMALLINT, TINYINT | Минимум/максимум | Значение исходного типа или NULL |
| SUM | Целые | Точная сумма через DECIMAL | BIGINT после проверки диапазона |
| SUM | DOUBLE | Сумма | DOUBLE или NULL |
| AVG | Целые и DOUBLE | SUM и COUNT(v) отдельными Arrow-столбцами | ROW(DOUBLE, BIGINT) |

Обычный GROUP BY допускает несколько ключей целых типов, BOOLEAN и VARCHAR.
Некоторые неявные приведения Trino создают Project между агрегацией и сканом;
такие планы могут остаться без pushdown даже для перечисленных типов.

## Контракт частичной агрегации

`FlightAggregation` хранит список `AggregateSpec`. Это описание конкретной
операции: функция, типизированный вход, выходной тип промежуточного состояния,
вычисляемые на Flight выражения, способ сборки состояния и пустое состояние.

- `FlightMetadata` проверяет запрос и ожидаемый промежуточный тип от Trino.
- `FlightQueries` строит SQL для Flight, сохраняя фильтры перед агрегацией.
- `FlightAggregationStates` проверяет Arrow и собирает Trino Blocks.
- Штатный FINAL Trino объединяет состояния. Алгоритмы агрегатов Trino не заменяются.

Для AVG нельзя усреднять готовые средние разных endpoints. Например, значения
10, 20 на первом endpoint и 30 на втором дают состояния (сумма=30, count=2) и
(сумма=30, count=1). Итог — 60 / 3 = 20.

В Trino 446 состояние AVG сериализуется в порядке `(sum DOUBLE, count BIGINT)`.
Для целых аргументов сумма считается после преобразования значений в DOUBLE,
как в штатном AVG Trino. NULL не входит в COUNT(v).

Для целочисленного SUM формируется `SUM(CAST(v AS DECIMAL(19, 0)))`. Сервер
возвращает DECIMAL(29, 0) через существующий путь decimal SUM. Коннектор переводит
точное значение в BIGINT с проверкой диапазона. Это сохраняет целые больше 2^53,
которые нельзя точно передать через DOUBLE. Переполнение промежуточного состояния
вызывает ошибку; финальное объединение сохраняет проверки Trino. Изменение порядка
сложения может изменить момент возникновения промежуточного переполнения.

## Пустые данные и ограничения

COUNT возвращает 0; SUM/MIN/MAX/AVG возвращают NULL. Для AVG коннектор создаёт
состояние `(0.0, 0)`, из которого FINAL получает NULL. Если endpoints нет вообще,
локальный synthetic split отдаёт нужные состояния без сетевого чтения Flight.
Пустая сгруппированная выборка не создаёт групп. HAVING выполняется после FINAL.

DOUBLE MIN/MAX пока не проталкиваются: семантика NaN у extrema Trino и DuckDB
различается. REAL, входные DECIMAL, строковые и временные MIN/MAX, DISTINCT,
GROUPING SETS и агрегатные FILTER/ORDER BY сохраняют обычное выполнение в Trino.
Если хотя бы один агрегат запроса неподдерживаемый, вся запрошенная агрегация
отклоняется коннектором. Изменение порядка суммирования DOUBLE может менять
младшие разряды результата; побитовое совпадение не обещается.

Это расширение не добавляет JOIN pushdown или обмен между Flight-нодами.
Все Trino-ноды должны использовать одинаковый engine patch и connector build:
JSON-модель handle изменилась с `counts` на `aggregates`.

## Проверки

Unit-тесты проверяют типы и отказ от неподдерживаемых контрактов, генерацию SQL,
коллизии имён, сериализацию handle, проверку Arrow, пустые состояния и переполнение.
Профиль `integration,patched-trino` сравнивает pushdown on/off на реальном Flight
с Parquet/DuckDB и Trino. Два endpoints имеют пересекающиеся ключи и разные
количества значений для AVG; проверяются NULL, HAVING, пустые выборки, суммы
больше 2^53, переполнение частичного/финального BIGINT SUM и NaN/±Infinity для
DOUBLE SUM/AVG. Task concurrency — 1 и 4.

Тестовый стенд использует один Flight-процесс и Trino coordinator, исполняющий
задачи. Он не заменяет multi-host тест, проверку полного дистрибутива и бенчмарки.

Проверка 2026-11-11: compile, Checkstyle и SpotBugs прошли; 755 unit-тестов
прошли по всем модулям. В WSL прошли 6 интеграционных тестов и 3 теста правила
планировщика, Maven завершил сборку с BUILD SUCCESS. При завершении этого запуска
Surefire сообщил о 30-секундном таймауте ожидания завершения fork JVM; результаты
тестов — 0 failures, 0 errors. Это предупреждение завершения тестового процесса
остаётся отдельным ограничением стенда.
